## 3. 지금 유효한 결정 (10/14 판 — 이유는 `docs/decisions/`, 뒤 번호가 앞 번호를 바꾼다. 10/6 주제 개편 E-01~E-25 · PC 배치 · MQTT · CI 뒤 10/14까지 E-26~E-111)

- **정본:** 이름 · 칸 · 형식은 IRD(`docs/02_인터페이스_IRD_*.md`)가 정본이다 — 이 프롬프트와 다르면 IRD를 따른다. 측정값은 `robot.yaml`. 10/14 데이터 · 이름 통일(E-111 A1 ~ C6)은 `docs/설명_데이터인터페이스_통일_*.md`.
- **이름(10/13 용어 B — E-94):** 진짜 젠가 블록이면 `block`, 설계 안 부품(블록 하나 크기의 자리)이면 `part`, 부품 그룹(덩어리)이면 `group`. 전체 부품 이름 `part_id` = `<design_id 대문자>_<part_name>`(예 `001_CHAIR_BENCH_V000_LEG_001_01`, 옛 `block_id`) · 부품 이름 `part_name` = `<역할>[_<옵션>]_<그룹 3자리>_<부품 2자리>`(옛 `block`) · AI 설계도 그룹 칸 `group`(옛 `part`) · 자재 `stock_id` `STOCK_001`(옛 `PART_001`). 진짜 블록인 것은 그대로: 스캔 `blocks/2`의 목록 `blocks` · `find_blocks` · YOLO · `block_size_m` · 장면 물체 `blk_<part_id>`. **부품 이름에서 설계 이름을 잘라 내지 말 것** — `CheckProgress.design_id`로(`BACK` · `BASE` · `BEAM`에도 `_B`가 있다). 역할 · 옵션 목록 = `src/d2_task/d2_task/roles.json`(맞는 것이 없으면 AI가 짓고 PR로 더함).
- **형식(10/14 E-111 C6 — 이름 하나로):** AI 설계도 **`parts/4.0`** = `{"schema":"parts/4.0","design_id","parts":[{"sequence","x","y","z","ori","role","group","stage","grasp"}]}`(mm, 설계 좌표계 · 방향 x·y·xe·ye·zx·zy, 옛 `order` → `sequence`). 레시피 = **`<design_id>_recipe.json`(`recipe/4.0` — 열쇠 `design_id`(옛 `model_id`) · `source_cad` · `stocks` · `template.composition`) + `<design_id>_placements.csv`(조립 방법 18칸, 전달 JSON `placements/4.0`, `recipe_sha256` 짝 확인)**. `get_design` 답 = `design/4.0`, `check_design` 답 = `check_result/3.0`. 그대로: `progress/2.0` · `build/2` · `state/2` · 스캔 `blocks/2`(번호 `scan_num`) · `scan_result/2.0`. 읽는 쪽은 `schema` 앞자리로 확인 — 다르면 거절(3.0 이하 레시피 · 설계도는 읽지 않음, IRD 6장).
- **정본 함수(E-111 C1 ~ C4 — 같은 표를 새로 만들지 말고 가져다 쓴다):** `d2_task.recipe_document` — `GRASPS`(설계 잡기 6개) · `part_name(group, part)` · `part_id(design_id, name)` · `recipe_sha256` · `same_major` · `RecipeDocument`; `d2_task.recipe_to_parts` — `ORIS` · `ori_extents`. 패키지 경계로 가져올 수 없는 복사본(`d2_motion` · `d2_vision` · 화면 TypeScript · `robot.yaml`)은 `tests/test_shared_tables.py`가 같은지 본다 — 한쪽만 고치면 CI가 잡는다. 변환기 ① = `d2_task.parts_to_recipe`(부품 JSON → 레시피), 변환기 ② = `d2_task.recipe_to_parts`(레시피 → 부품 JSON).
- **판단은 한 곳:** 멈출지 = 정지 노드 · 진행표 = 작업 판단 · **설계가 쌓을 만한지 = 검사 묶음(task)** · **무엇을 쌓을지 = 사람([조립])** · 장면 = 장면 관리 · DB = HMI `design_store`. LLM 호출은 HMI `design_gen` 한 곳.

## 5. 일하는 방식

- **하루:** `/today 박진용` → 작업 → `/wrap W번호`. 처음 한 번은 `/start 박진용`.
- **말:** 박진용에게 쉬운 한국어로 짧게. 명령은 복사해 쓸 수 있게. 사실(측정값 · 좌표 · 이름)을 지어내지 않고, 문서와 다르면 묻는다.
- **다른 파트:** 그 파트 파일은 고치지 않고, 박진용이 보낼 짧은 메시지를 써 준다.
- **ROS 없는 계산 파일**(검사기 · 변환기 · 스캔 추론 · 생성 · 저장소)은 `pytest`로 로봇 없이 먼저 시험한다.
- **보고**(하루 끝 · 측정이나 결정이 생기면):
  ```
  [박진용 / 로봇 동작] 날짜
  - 한 것 / 잰 값·정한 것(숫자·단위) / 막힌 것 / 다른 파트에 필요한 것 / 변경 파일
  ```
- 30분 넘게 막히면 팀에 공유를 권한다.
