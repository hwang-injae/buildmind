# 복구 절차 — 로봇이 멈췄을 때 다시 돌리기 (W070)

> 시연 · 리허설 · 실기 중 로봇이 섰을 때 이 순서대로 한다. 근거: SDD 7.3(정지 · 실패 뒤 다시 시작) · 8.1(정지 구조), 10/7 실기에서 겪은 SAFE_OFF 복구.
> 작성 박진용(로봇 동작 · 안전 감시), 10/7. 스캔 · 복제 부분은 스캔 기능(W116) 실기 뒤 다시 확인한다(→ W116은 10/13 실기 끝 — §6).
> 10/7 저녁 IRD · SDD 5장(작업 관리자 상태)에 맞춰 시간 초과(`TIMEOUT`) · 웹 끊김(`WAIT_HMI`) · 흩뿌린 공급(`WAIT_SUPPLY` · `tilted_block`) 줄을 더했다(문서담당). 10/9: 그리퍼 응답 없음 · 피드백 없음 = 작업 관리자 `ERROR`(정지 노드 잠금 아님, E-74 · §31) · 알림 `no_match_block`(E-73) 줄을 고쳤다(PM). 10/14(PM): 정지 뒤 [초기화] · [그리퍼 열기] · [정리 끝](E-98 · E-101 — §4-1은 W183 #157 글 그대로, 끝 줄 '[출발]'은 지금 [조립]) · 받침 경유 헛잡음 · 시간 제한 120초(E-103) · 공급 칸 없앰(E-103 ⑤) · 키 정지 안 씀(10/14 PL) · 버튼 이름 [출발] → [조립]을 맞췄다(E-96). 10/15(PM): 음성 '정지'([🎤 말로 정지(듣기 시작)]) · 시간 초과 뒤 정지 확인 전 `stop_pending`(E-117) · 그리퍼 쥔 채 안내 '[정지] → [그리퍼 열기] → [다시 시작]'(E-114 꼴, 10/14 PL) · 장면 비우기 시점(E-120) · [취소] · 첫 이동 저속 값(`recover.speed_ratio` 0.4)을 지금 코드(main 2d74462)에 맞췄다.

## 0. 먼저 알 것

- **로봇이 서면 정지 노드가 잠근다.** 잠기면 집기 · 놓기 · 이동 명령을 모두 거절한다(결과 이유 `STOPPED`, 실행 중 멈춘 목표는 `CANCELED` — 왜 멈췄는지는 `/d2/safety/state` reason에만 있다, 10/8 E-62). 잠금은 **[다시 시작](= `/d2/safety/resume`) 또는 [초기화] 뒤 [정리 끝]**(10/13 E-98 ② — 둘 다 `safety/resume`, §4-1)으로만 풀린다.
- **로봇 알람이 남아 있으면 [다시 시작]을 해도 0.5초 안에 다시 잠긴다.** 알람(아래 표의 SAFE_OFF · SAFE_STOP · 비상정지)을 먼저 없애야 한다.
- **[다시 시작] 뒤에는 늘 '진행 확인부터'** — 작업 관리자가 관측 자세에서 놓인 블록을 다시 보고, 이미 놓인 블록은 건너뛰고 이어서 쌓는다(SDD 7.3). 관측 자세로 가는 첫 이동은 저속(`recover.speed_ratio` 0.4 — 평소 `speed_scale` 0.5 × 0.4 = 0.2, 10/14 박진용)이다.
- **잠기지 않고 멈추는 상태도 있다** — `WAIT_SUPPLY`(공급 채우기) · `WAIT_HMI`(웹 끊김)는 정지가 아니라 기다림이다. [다시 시작]이 아니라 화면 **[계속]**(공급 기다림이면 버튼 글 '블록 채웠어요 · 계속')으로 이어 간다(§2 표의 '잠금 아님' 줄).
- **블록을 쥔 채 [다시 시작]하면 작업 관리자는 ERROR로 간다** — 안내 글 '그리퍼가 블록을 쥐고 있어 이어 갈 수 없어요 → … → 블록을 받칠 사람과 함께 [정지] → [그리퍼 열기] → [다시 시작]'(10/14 PL — E-114 꼴). [그리퍼 열기]는 잠긴(STOPPED) 때만 받으므로 [다시 시작]만 다시 누르면 ERROR를 되풀이한다 — **블록을 받칠 사람과 함께 [정지] → [그리퍼 열기] → [다시 시작]**(§4-1). 정지가 아닌데 그리퍼가 블록을 쥐고 있으면 화면이 [조립] · [스캔]을 끄고 같은 순서를 안내한다.
- 그리퍼 명령은 잠긴 중에도 받는다 → 잠긴 상태에서 블록을 손으로 받치고 그리퍼를 열 수 있다(화면은 [그리퍼 열기] — §4-1).
- **시간 초과 뒤 정지 확인 전 `ERROR`(알림 `stop_pending`)에서는 화면 [다시 시작]이 꺼진다** — '정지 확인 전이에요 — [정지]를 누른 뒤 [다시 시작]'(10/14 E-117). 작업 관리자가 정지 신호(stopped)를 받기 전에는 [다시 시작]을 무시하기 때문이다. [정지](또는 펜던트)로 STOPPED가 된 뒤 [다시 시작]한다.
- **장면(MoveIt)의 놓인 블록은 실물과 같게 비운다(10/14 E-120):** [조립] 출발 · [초기화] → [정리 끝] 때 비우고, 조립 끝(DONE) · 그냥 정지 → [다시 시작] · [취소] 때는 그대로 둔다. 그래서 **[정리 끝]은 조립 자리를 실제로 치운 뒤에만 누른다** — 안 치우고 누르면 장면에는 없는 블록이 작업대에 남아 MoveIt이 그 블록을 피하지 않는다.
- **W144 녹화(`w144_record`)를 켠 판 — 조립 중 정지하면 녹화를 바로 닫는다**(초당 2장으로 줄이고 원본은 지움 · [다시 시작]으로 이어 가면 새 폴더로 다시 엶 · 끝 · [초기화]면 다시 안 엶 — #185 박진용, 10/15 PL '가'로 9차에 넣음). 옛 판(10/14)은 정지 뒤 안 닫혀 V008 24 GB · V009 57 GB가 쌓였다. 녹화는 기본 끔 · 자료 판만 켜고 디스크 남은 양 확인(`df -h ~/d2_data`).
- **이어 가지 않으려면:** 잠긴(STOPPED) 때는 [초기화] — §4-1, 출발 대기(READY) · 오류(ERROR) · 스캔 확인(SCAN_REVIEW) 때는 [취소] → 대기(IDLE).

## 1. 공통 순서 (어떤 이유로 멈췄든)

1. **원인을 본다** — 터미널 A에서 정지 상태와 로봇 상태를 읽는다(§3).
2. **원인을 없앤다** — §2 표대로.
3. **쥔 블록이 있으면 뺀다** — §4.
4. **사람이 작업대 밖에 있는지 본다.**
5. **[다시 시작]** — 화면 [다시 시작] 버튼, 또는 터미널 A에서 `resume`(버튼이 꺼져 있고 '정지 확인 전이에요'가 보이면 [정지]부터 — §0).
6. **이어서 돌린다** — 팀 흐름이면 작업 관리자가 RECOVER → 진행 확인부터 자동으로 이어 간다. 시험 도구(`run_recipe`)면 남은 블록만 다시 실행한다(§5).

**SAFE_OFF가 생기는 때(10/7 실기):** 펜던트에서 안전 설정 화면에 들어가면 서보가 꺼진다(SAFE_OFF). 이때는 ROS에서 서보 켜기(`set_robot_control 3`)를 보내도 `success=True`만 오고 상태가 안 바뀐다 — 제어권이 펜던트로 넘어간 것으로 본다. **브링업을 다시 켜면** `INITIAL CONTROL_SERVO_ON` → STANDBY로 돌아온다. 실기 중에는 펜던트 안전 설정 화면에 들어가지 않는다.

## 3. 명령 (터미널별)

새 터미널은 늘 이 줄부터:
```bash
cd ~/rokey_9_pjt2_D2 && source /opt/ros/jazzy/setup.bash && source ~/cobot2_ws/install/setup.bash && source install/setup.bash
```

### 3-1. 터미널 A — 상태 보기 · 잠금 풀기
```bash
ros2 topic echo --once /d2/safety/state                                                    # stopped · locked · reason
ros2 service call /dsr_controller2/system/get_robot_state dsr_msgs2/srv/GetRobotState      # 1 STANDBY 이어야 다시 돈다
ros2 service call /d2/safety/resume std_srvs/srv/Trigger                                   # [다시 시작] — 원인을 없앤 뒤에만
```

### 3-2. 브링업 다시 켜기 (SAFE_OFF · 그리퍼 응답 없음)
- **터미널 1 (브링업)**: Ctrl+C로 끈다 → 다 꺼진 것 확인(`ps -ef | grep ros2_control_node` 가 비어야 함 — **두 개가 겹쳐 뜨면 제어기가 'already active'로 안 붙는다**) → 다시 켠다.
  ```bash
  ros2 launch d2_bringup real_moveit.launch.py mode:=real host:=192.168.1.100
  ```
  로그에 `ROBOT_STATE : STATE_STANDBY` 와 `You can start planning now!` 가 나오면 됨.
- **터미널 2 (노드 4개)**: Ctrl+C로 끄고 다시 켠다(브링업을 다시 켜면 노드도 다시 켠다).
  ```bash
  ros2 launch d2_bringup robot_nodes.launch.py mode:=real
  ```
  `[집기·놓기] 준비 끝` 이 나오면 됨. 이때 정지 노드는 새로 켜져 잠금이 없다.

런치는 **패키지 이름으로** 실행한다(`src/...` 경로로 실행하면 `__pycache__` 가 생긴다 — 10/7 `setup.py` 수정으로 빌드는 안 깨지지만 습관으로).

## 4. 블록을 쥔 채 멈췄을 때

1. 사람이 블록을 손으로 받친다(펜던트 든 사람 말고 한 사람 더).
2. **터미널 A** — 그리퍼를 연다(잠긴 중에도 받는다):
   ```bash
   ros2 service call /d2/gripper/command d2_interfaces/srv/GripperCommand "{width_m: 0.0865, force_n: 10.0}"
   ```
   - **그리퍼가 응답하지 않아 열리지 않으면(전원 · 연결 끊김 — `GRIPPER_NO_RESPONSE`):** RG2는 전원이 끊겨도 쥔 힘을 유지한다(제조사 자료). 블록을 손으로 받친 채 그리퍼 전원 · 연결을 다시 넣고, 응답이 오면 위 명령으로 연다. **다시 켜질 때 그리퍼가 스스로 움직이는지는 확인 안 됨**이라 받치는 손을 떼지 않는다(10/9 PL 결정 4).
3. 블록을 빼서 공급 영역 테이프 안(공급 칸은 10/13 없앰)에 다시 놓는다(놓던 블록이면 작업 관리자가 진행 확인으로 '없음'을 보고 다시 집는다).
4. 그다음 [다시 시작]. 화면으로 하려면 §4-1 — [정지]로 잠금 → 블록을 받치고 [그리퍼 열기] → [다시 시작](10/14 PL).

### 4-1. 화면 [초기화] · [그리퍼 열기]로 정리할 때 (W183 · W184, 10/13 PL)

1. 멈춘 뒤(STOPPED, 잠김) 화면 [초기화] → 확인. 작업 관리자가 이번 조립 기록을 STOPPED로 닫는다. **잠금은 그대로, 로봇은 움직이지 않는다.** 작업 관리자는 STOPPED에서 받은 `cancel`을 화면 · 음성 가리지 않고 같게 처리한다(E-101 ③ — 지금 `voice.py`는 `cancel`을 보내지 않는다).
2. 블록을 쥐고 있으면 사람이 받친 채 화면 [그리퍼 열기]. 그리퍼는 0.0865 m · `gripper.force_n`으로 열리고, 화면은 열리는 동안(`gripper_opening`) 조립 · 스캔 · 다시 열기 버튼을 끈다. 끝나면 `gripper_done`(성공 · 실패 글자).
3. **그리퍼 답이 끝내 오지 않으면(`gripper_opening`이 풀리지 않음):** 작업 관리자는 차단을 스스로 풀지 않는다. 블록을 받친 채 그리퍼 전원 · 연결을 확인하고(위 4절 2), 필요하면 3-2처럼 노드를 다시 켠다. 그다음 **task 노드를 다시 켜야** 차단이 풀린다(task를 띄운 터미널에서 Ctrl+C → 같은 명령으로 다시 실행, 예: `ros2 run d2_task task`).
4. 그리퍼에 쥔 블록, 조립 자리의 구조물, **받침(임시 적재대) 위 블록**을 모두 치운다. 코드의 받침 기록은 새 출발 때 비워지지만 실물은 사람이 치워야 한다. 아직 쥐고 있으면 알림 창이 '그리퍼에 블록이 있어요 — 블록을 받치고 [그리퍼 열기]'로 경고한다(버튼은 막지 않음).
5. 화면 [정리 끝] → `safety/resume` → RECOVER → IDLE(로봇 안 움직임). 이때 MoveIt 장면의 놓인 블록도 비운다(E-120 — 그래서 4를 다 한 뒤에만). 설계를 다시 고르고 [조립] — E-96.

## 5. 다시 이어서 돌리기

- **팀 흐름(작업 관리자 · task 노드)**: [다시 시작]만 하면 된다 — STOPPED → RECOVER → 쥔 블록 확인 → CHECK(관측 자세 저속 · 진행 확인) → 이미 놓인 블록은 건너뛰고 이어서(장면의 놓인 블록은 그대로 — E-120). 조립 중이 아니었으면(스캔 중 포함) IDLE로 가니 설계를 다시 고르고 [조립] — E-96. 이어 가지 않으려면 [다시 시작] 대신 [초기화] — §4-1.
- **시험 도구(`run_recipe`) — 터미널 B**: 진행 확인이 없으므로 **남은 순번만** 다시 준다. 예: 7번째 블록에서 멈췄고 7번이 안 놓였으면
  ```bash
  ros2 run d2_motion run_recipe --steps 7-11      # 번호 1 → y
  ```
  반쯤 놓인 블록은 사람이 치우거나 바로 놓은 뒤 실행한다.

## 6. 스캔 · 복제 중 멈췄을 때 (코드 기준 — W116(10/13) 실기는 복제 조립 중 [정지]까지, 10/14 W191은 자유 모양 스캔 → 저장 → 복제 DONE — 04 AC-7)

- 스캔 촬영 · 추론 중(SCAN_MOVE · SCAN_CAPTURE · SCAN_INFER)에 멈추면: [다시 시작] → 작업 관리자 IDLE → **[스캔]을 처음부터 다시** 누른다(SDD 7.3 — 중간부터 잇지 않는다).
- 스캔 결과 확인 화면(SCAN_REVIEW)에서 멈추면: [다시 시작] → 작업 관리자 IDLE. 저장 전이면 다시 [스캔], 저장 뒤면 그 설계를 골라 [조립](`select_design` → `start`, E-96). 멈추지 않았는데 그만두려면 결과 화면 [취소] → IDLE.
- 조립 끝(DONE)에서 바로 [스캔]할 수 있다(E-102 ①) — 다 지은 가구는 장면에 그대로 두고 촬영 자세로 움직인다(E-120 — 10/14 실기 확인).
- 복제 조립 중에 멈추면: 일반 조립과 같다(§5 팀 흐름).

## 7. 하지 않는 것

- 원인을 없애기 전에 [다시 시작]을 여러 번 누르지 않는다(알람이 남아 있으면 바로 다시 잠긴다).
- 실기 중 펜던트 안전 설정 화면에 들어가지 않는다(서보가 꺼져 브링업을 다시 켜야 한다).
- 브링업을 두 개 띄우지 않는다.
- 블록을 쥔 채 그리퍼를 열지 않는다(받치는 사람 없이).
- 블록을 쥔 채 [다시 시작]만 되풀이하지 않는다 — [정지] → [그리퍼 열기] → [다시 시작](§0 · §4-1).
- [초기화] 뒤 [정리 끝]은 다 치운 뒤에만 누른다 — 누르면 잠금이 풀린다(E-98 — 정리하는 동안 잠금 유지).
