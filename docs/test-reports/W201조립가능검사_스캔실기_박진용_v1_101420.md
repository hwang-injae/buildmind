## 4. 사례별 분석

### 4-1. 2 × 2 를 맞게 잡음 (#3 · #5) ✅
- **#3 눕힌 6개**: x 방향 블록이 x −37.5 · 37.5 두 줄, y −25 · 0 · 25 세 칸으로 붙어 있다. 6개 모두 R5.
  예: 1번 — 좌우로 잡으면 4번, 앞뒤로 잡으면 2번이 막음. 가운데 5번 — 좌우는 2번, 앞뒤는 4 · 6번이 막음.
- **#5 세운 4개**: `zy` 4개가 x ±12.5 · y ±7.5에 틈 0으로 붙어 있다. 4개 모두 R5.
- 바로 앞 #4(세운 3개 한 줄, 틈 있음)는 '조립 가능'이었다 — **붙은 2 × 2만 정확히 가려낸다.**

### 4-2. 조립 가능을 맞게 냄 (#4 · #6)
- #6: 1층 · 6층의 연짝 3개는 옆(좌우)은 붙어 있어도 블록 끝(앞뒤)이 비어 있어 한쪽부터 놓으면 손가락 자리가 남는다 → 가능.
  사방이 막힌 곳이 없어서 맞는 판정이다.

### 4-3. 위층 2 × 2가 있는데 아래층에서 먼저 걸림 (#1 · #2)
- 두 판 모두 4층에 x 방향 블록 6개(2줄 × 3)가 있다. **두 판 다 4층 6개만 따로 떼어(높이만 바닥으로) 돌리면 6개 모두 R5(조립 불가)** — 의도한 이유를 맞게 잡는다.
- 그런데 W201은 R0을 구조 전체에서 먼저 보고, 순서를 아래층부터 찾다가 **처음 막히는 층에서 멈춘다.** 그래서 4층까지 가지 못했다.
  - #1: 2층 5번이 스캔 **추정 블록**(`inferred: true`)인데 방향이 x(나머지 y) → R0.
    추정 블록을 빼고 돌리면 R2(2층 6번이 아래 3번에 12.5 mm만 걸침)로 바뀐다.
  - #2: 3층 y 블록 4개(x −50 · −25 · 25 · 50)가 기둥(x ±37.5) 위에 반씩 걸쳐 → R2 4개.
    실물이 정말 반씩 걸친 모양이면 맞는 판정이고, 기둥 위에 바로 올린 거면 스캔이 반 칸 어긋난 것이다(실물 확인 필요).

### 4-4. 안정성(R3)만 걸림 (#7 · #8)
- 두 판 모두 **블록 하나만 아래 블록에서 12.5 mm 비켜** 잡혀서 무게중심 여유가 2.5 mm로 나왔다.
  - #7: 2층 4번이 x 18.8(아래 1층 2번은 x 31.2)
  - #8: 3층 5번이 y −18.8(아래 2층 3번은 y −31.2)
- **R3만 끄면 두 판 모두 조립 가능**(순서 1 → 12) — 손가락 · 받침 순서 · 닿는 면 · 층 방향은 다 통과.
- 12.5 mm는 스캔 격자에서 블록 폭(25 mm)의 반 칸이다. 실물을 일부러 밀어 둔 게 아니라면 스캔이 그 블록 자리를 반 칸 잘못 잡은 것이다.

## 5. 정리

**W201 계산**
- 2 × 2(사방이 막힌 배치)는 눕힘 · 세움 모두 R5로 정확히 잡았다(#3 · #5, #1 · #2의 4층만 따로 돌린 것).
- 틈이 있는 배치 · 연짝 · 기둥은 '조립 가능'과 순서를 맞게 냈다(#4 · #6).
- 계산 시간: 스크립트 한 번(파이썬 시작 포함) 0.10 s(#1, 15개) · 0.11 s(#8, 12개).

**걸리는 것 — 스캔 쪽 오차**
1. **반 칸(12.5 mm) 밀림**: #2 · #7 · #8(그리고 #1 추정 제외판). W201이 R2 · R3로 '조립 불가'를 낸 원인.
2. **안 보이는 칸을 블록으로 채움**: #1 2층 5번(방향도 다르게). 같은 날 18:04 스캔 `R20261014_180438_c0f6`(실물 6개)도
   1층 가운데 빈칸(2층 3개가 위를 다 덮음)을 채워 7개로 저장됨 — 2층은 1층 양쪽 2개로도 받쳐지는데 채웠다.
3. **세운 블록을 두 단 쌓은 다리**: 18:56 · 18:57 스캔(`R20261014_185604_222c` 0.71 · `R20261014_185648_c318` 0.56)이
   설명률 0.8 미만으로 스캔 실패(조립 자리 안에 다른 물건은 없었음 — 사진 확인).

**W201을 웹에 연결할 때 알아 둘 것**
- 지금처럼 처음 막히는 층에서 멈추면, 위층의 진짜 이유(2 × 2)가 가려진다. 화면에는 첫 실패만 보여도 되지만, 스캔 오차로 아래층이 걸린 경우 사람이 원인을 헷갈릴 수 있다.
- R2 · R3가 '딱 12.5 mm'로 걸리면 스캔 반 칸 오차일 가능성이 높다 — 안내 글에 '다시 스캔'을 같이 띄우는 게 좋다(지금 R2 글에는 있음).

## 부록 — 재현 스크립트

로봇 PC에서 `python3 feas.py ~/d2_data/scan/<폴더>` (ROS 환경 변수 없이: `env -u PYTHONPATH`).

```python
"""스캔 blocks.json 하나로 W201 조립 가능 검사만 돌려 본다(로봇 · ROS 없음, 시험용)."""
import json, sys
from pathlib import Path
import yaml
R = Path.home() / 'rokey_9_pjt2_D2'
sys.path.insert(0, str(R / 'src/d2_task'))
from d2_task.design_checker import DesignChecker
from d2_task.assembly_feasibility import AssemblyFeasibility
p = Path(sys.argv[1]); p = p / 'blocks.json' if p.is_dir() else p
blocks = json.loads(p.read_text())['blocks']
parts = [{'sequence': b.get('scan_num', i + 1), 'x': b['x'], 'y': b['y'], 'z': b['z'], 'ori': b['ori']} for i, b in enumerate(blocks)]
cfg = yaml.safe_load((R / 'src/d2_robot/d2_bringup/config/robot.yaml').read_text())
res = AssemblyFeasibility(DesignChecker(cfg)).check_parts(parts, snap_to_grid=True)
print(f'블록 {len(parts)}개 →', '조립 가능' if res['ok'] else '조립 불가')
print('순서:', res.get('order'))
for f in res.get('failures') or []:
    print(' -', f)
```

R3를 끈 판정은 `chk = DesignChecker(cfg); chk.margin_mm = -1e9` 로 만든 객체를 넘겼다.
