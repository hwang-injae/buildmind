# 웹 PC 새로 셋팅 — 고장 난 웹 PC 대신 다른 PC를 웹 PC로 (v1_101509)

> 10/15 09시 PL: 웹 PC가 고장 나 다른 PC를 웹 PC로 설정한다. 이 문서는 저장소에 이미 있는 절차([web/README](../web/README.md) 1-B · 1-C · '두 PC Wi-Fi 연결', [환경 문서](env/README.md) 6-1 · 7 · 9장)를 **새 PC 한 대 기준으로 순서대로** 모은 것이다. 새로 정한 규칙은 없다.
> **웹 PC = ROS 없음.** 컨테이너 3개(`mosquitto` 브로커 · `db` PostgreSQL · `web` 화면 + backend) + 호스트 프로그램 2개(`claude_bridge` 설계 AI 중계 · `voice.py` 음성). 로봇 PC는 그대로이고 **다리(`d2_bridge`)가 붙을 주소만** 새 웹 PC IP로 바꾼다.

## 0. 먼저 정할 것 · 챙길 것

| 무엇 | 어떻게 |
|---|---|
| 새 웹 PC | Ubuntu 24.04 · 로봇 PC와 **같은 Wi-Fi** · 마이크 · 스피커(음성 쓸 때) |
| 새 웹 PC Wi-Fi IPv4 | 새 PC에서 `ip -4 addr show` — 이하 `<웹IP>` (지금까지 옛 웹 PC = 172.24.2.213) |
| 로봇 PC Wi-Fi IPv4 | 로봇 PC에서 `ip -4 addr show` — 이하 `<로봇IP>` (지금까지 172.24.0.137, 바뀌었는지 꼭 확인) |
| 옛 웹 PC에서 살릴 것(디스크를 읽을 수 있으면) | ① `web/db/data/` — DB 데이터(AI · 스캔으로 만든 설계 · 조립 기록) ② `web/backend/data/` — JSON 저장소(DB를 안 켰던 때 것) ③ `web/backend/models/hello_rokey_8332_32.tflite` — 음성 시동어 모델(**저장소에 없음** — 옛 PC에서 가져오거나 민범진에게 받음) |
| 못 살리면 | 빈 DB로 시작 — 기본 설계 4개는 web이 켜질 때 레시피에서 다시 등록되지만, **AI · 스캔으로 만든 설계와 조립 기록은 없어진다**. 시연 전이면 필요한 설계를 다시 만든다 |
| 키 · 비밀번호 | OpenAI 키(음성 받아 적기용)와 DB 비밀번호는 `web/.env`에만 넣는다 — 채팅 · 문서 · 커밋에 쓰지 않는다. 옛 `.env`를 살렸어도 키는 PL · 한석형에게 확인 |

## 1. 설치 (새 웹 PC — 사람이 직접, 설치 전 PL 확인)

```bash
sudo apt update
sudo apt install -y git docker.io docker-compose-v2 mosquitto-clients python3-pip python3-venv libportaudio2
sudo usermod -aG docker $USER          # 한 번 로그아웃했다 들어오면 sudo 없이 docker
docker --version && docker compose version
```

- **Node 24**(화면 빌드용 — 우분투 apt 는 18 이라 안 됨): 사용자 폴더에 nvm → 터미널 다시 열고 `nvm install 24`(방법은 [web/README](../web/README.md) 1-B 첫 줄).
- **Claude Code**(설계 AI): 데스크톱 앱 또는 `claude` 명령을 깔고 **이 PC에서 로그인**한다. 중계는 그 계정의 구독 한도를 쓴다(키 없음). 데스크톱 앱이 깐 것은 중계가 알아서 찾는다.
- **음성 라이브러리**(voice.py — 호스트에서 돈다): 가상 환경을 하나 만들어 그 안에 `sounddevice` · `openwakeword` · `openai` · `paho-mqtt` · `numpy`(2 아님 — `numpy<2`). 이 가상 환경으로 `voice.py`를 돌린다.

## 2. 저장소 받기

```bash
git clone https://github.com/hwang-injae/rokey_9_pjt2_D2.git ~/rokey_9_pjt2_D2
cd ~/rokey_9_pjt2_D2 && git checkout main && git pull && git log -1 --oneline   # 오늘 9차 push(11:30) 뒤 판인지 확인
mkdir -p web/backend/data                                                          # web 컨테이너가 쓰는 폴더 — 먼저 만들어 둔다
```

옛 PC에서 살린 것이 있으면 여기서 제자리에 복사한다(`web/db/data/` · `web/backend/data/` · `web/backend/models/hello_rokey_8332_32.tflite`). DB 데이터 폴더는 PostgreSQL 16 것 그대로 옮기고, 컨테이너가 처음 뜰 때 권한 오류가 나면 `docker compose logs db`로 본다.

## 3. `web/.env` 만들기

```bash
cd ~/rokey_9_pjt2_D2/web && cp .env.example .env && nano .env
```

| 칸 | 넣을 값 |
|---|---|
| `OPENAI_API_KEY` | 음성 받아 적기 키(PL · 한석형) — 설계 AI는 이 키를 안 씀 |
| `D2_LLM_MODEL` | 비움(= opus) |
| `COMPOSE_PROFILES` | `db` — 이 줄이 없으면 db 컨테이너가 안 뜸(시연 웹 PC는 DB 켬, E-112) |
| `POSTGRES_PASSWORD` | 새 비밀번호(옛 DB 폴더를 옮겼으면 옛 비밀번호 그대로) |
| `DATABASE_URL` | `postgresql://d2:<위 비밀번호>@db:5432/d2` |
| 나머지 | 그대로(`MQTT_HOST` 등은 compose 가 덮어씀) |

## 4. 화면 빌드

```bash
cd ~/rokey_9_pjt2_D2/web/frontend && npm ci && npm run build     # → web/frontend/out (컨테이너가 읽기 전용으로 연결)
```

## 5. 방화벽 — 브로커를 열기 **전에**

브로커(1883)는 새 웹 PC Wi-Fi IPv4에만 열고, 로봇 PC만 받는다(인증 없음 — #136). 저장소 맨 위에서:

```bash
cd ~/rokey_9_pjt2_D2
sudo bash tools/install_mqtt_access.sh <로봇IP> <웹IP>                 # 재부팅해도 다시 적용되게 설치(브로커가 떠 있으면 거절)
sudo bash /usr/local/libexec/d2-mqtt-access.sh check <로봇IP> <웹IP>   # 통과해야 다음 단계
```

## 6. 컨테이너 켜기

```bash
cd ~/rokey_9_pjt2_D2
D2_WEB_IPV4=<웹IP> WEB_UID=$(id -u) WEB_GID=$(id -g) docker compose -f web/compose.yaml up -d --build   # 처음 한 번 --build
D2_WEB_IPV4=<웹IP> WEB_UID=$(id -u) WEB_GID=$(id -g) docker compose -f web/compose.yaml ps            # mosquitto · db · web 이 Up
D2_WEB_IPV4=<웹IP> WEB_UID=$(id -u) WEB_GID=$(id -g) docker compose -f web/compose.yaml logs -f web   # '[웹] 저장소 = …' · 브로커 연결 · 기본 설계 등록
```

- compose 명령은 `ps` · `logs` · `restart` 모두 앞의 세 값(`D2_WEB_IPV4` · `WEB_UID` · `WEB_GID`)이 있어야 돈다.
- web 이 DB에 30초 안에 못 붙으면 다시 켜지기를 되풀이한다 — `docker compose … logs db web`으로 까닭을 본다(비밀번호 · `COMPOSE_PROFILES` 확인).

## 7. 호스트 프로그램 2개 (각각 터미널 하나)

```bash
cd ~/rokey_9_pjt2_D2
# 설계 AI 중계 — 꼭 --host 172.17.0.1(docker0). 먼저 점검, ❌ 없으면 켬
python3 web/claude_bridge.py --check --host 172.17.0.1
python3 web/claude_bridge.py --host 172.17.0.1
# 음성 — 1장에서 만든 가상 환경의 python 으로. 브로커가 Wi-Fi IPv4 에만 열려 있어 --host <웹IP>
<가상환경>/bin/python web/backend/voice.py --check --host <웹IP>    # 마이크 · 스피커 · 시동어 모델 · 키 · 브로커 모두 ✅
<가상환경>/bin/python web/backend/voice.py --host <웹IP>
```

## 8. 로봇 PC 쪽 — 다리 주소만 바꾸기

로봇 PC의 다리를 새 웹 PC로 붙인다(로봇 PC의 다른 노드는 그대로).

```bash
# 로봇 PC — 다리를 끄고 새 주소로 다시 켬
ros2 run d2_bridge bridge --ros-args -p mqtt_host:=<웹IP>
# 로봇 PC에서 확인
python3 tools/check_web_ports.py <웹IP>                      # 1883 = 연결됨(true) · 8000 = 안 됨(false)이 정상
mosquitto_sub -h <웹IP> -t 'd2/bridge/alive' -v               # 1초마다 alive true
```

`robot.yaml`의 `mqtt.host`를 고치는 대신 실행 때 `mqtt_host`를 주는 것은 저장소 파일을 안 바꾸려고다(로봇 PC 파일은 main 그대로).

## 10. 바뀐 것 알리기

- 웹 PC가 바뀌었다는 것과 `<웹IP>`를 팀 공지에 적는다(메시지 답변 세션). 로봇 PC 담당은 8장으로 다리를 다시 켠다.
- 앞으로 main을 받은 뒤 웹 PC 반영은 늘 같다: 화면 빌드(`npm ci && npm run build`) → `docker compose … restart web` → 호스트 프로그램이 바뀌었으면 그 터미널에서 다시 켬([환경 문서](env/README.md) 7장 끝).
